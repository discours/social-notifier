# social-radar — договор для агентов

Сервис уведомлений: GitHub Actions раз в 10 минут читает VK, Instagram и Facebook и пишет в Telegram. Устройство и настройка — [README.md](README.md) и [docs/setup.md](docs/setup.md).

## Гейт

```bash
npm run typecheck && npm test
```

Зелёный — нулевой код возврата обеих команд. CI (`.github/workflows/ci.yml`) гоняет то же на Node 22 и 24.

## Правила

- Node 22.18+, TypeScript исполняется напрямую (type stripping). Только стираемый синтаксис: без `enum`, `namespace`, parameter properties; импорты с расширением `.ts`. Зависимостей во время работы нет — новая требует обоснования.
- **Логи публичные.** Секреты не попадают в лог, алерт и состояние: тексты ошибок проходят через редактор (`makeRedactor`). Не логировать адреса запросов (у Telegram токен в пути), заголовки, тела ответов API целиком. Тексты постов и названия страниц — публичный контент; обычный запуск их не логирует, dry-run и проба — можно.
- Доставка «хотя бы раз»: пост снимается с очереди после того, как Telegram принял его сообщение. Сбой источника или формата ответа должен доходить до алерта (`collectPosts` превращает целиком неразобранный ответ в `bad_response`), а не превращаться в «новых постов нет».
- Токены — только в заголовке или теле запроса, никогда в query string. Тест `токены VK и Meta не попадают в адрес запроса` это проверяет.
- Запросы к Graph API — с явным `fields`: без него ответ `me/accounts` содержит токены страниц.
- Workflow с секретами — только `schedule` и `workflow_dispatch`; `pull_request_target` не использовать. Экшены закрепляются по SHA с комментарием версии.
- Повреждённое состояние — ошибка запуска, а не тихий сброс: сброс прислал бы архив постов заново.
- Тексты для людей (сообщения, алерты, логи, комментарии) — по-русски; код и идентификаторы — по-английски.
- Тесты — `node:test`, внешние API подменяются `FakeWorld` из `test/helpers.ts`. Новая логика отбора или отправки получает тест, который краснеет при её поломке.
