# Как добавить сеть

Сеть — это адаптер: файл в `src/sources/`, который знает поля источника в конфиге, нужные секреты и способ получить последние посты. Ядро радара — очередь, группировка, алерты, состояние — о сетях ничего не знает.

Образцы: [`bluesky.ts`](../src/sources/bluesky.ts) — сеть без ключа, [`youtube.ts`](../src/sources/youtube.ts) — ключ в заголовке и два запроса, [`x.ts`](../src/sources/x.ts) — платная сеть, которая просит только новые посты.

## Шаги

1. **Адаптер** `src/sources/<сеть>.ts`: интерфейс источника (`type` и свои поля) и объект `SourceAdapter` из [`adapter.ts`](../src/sources/adapter.ts):
   - `parse` проверяет поля из конфига. Всё, что попадёт в адрес запроса, проверяется регулярным выражением: ID — цифрами, хэндлы — по синтаксису сети.
   - `fetch` возвращает не больше `ctx.config.fetchLimit` последних постов через `collectPosts`. Нераспознанный элемент считается, а не отбрасывается молча: если не разобрался весь ответ, это ошибка формата и, со второго запуска, алерт.
   - Ошибки API превращаются в `SourceError` с типом (`auth`, `permission`, `billing`, `rate_limit`, `config`, `http`, `bad_response`): по типу алерт подсказывает, что делать.
   - Чужое (репосты, приватные записи) отфильтровывается до `collectPosts`, иначе оно засчитается как мусор в ответе.
2. **Реестр** [`src/sources/index.ts`](../src/sources/index.ts): тип источника — в объединение `SourceConfig`, адаптер — в `ADAPTERS`. Если забыть одно из двух, проверка типов не пройдёт.
3. **Секрет**, если он нужен: имя — в `SOURCE_SECRETS` ([`src/env.ts`](../src/env.ts)) и в `secrets` адаптера, строка `ИМЯ: ${{ secrets.ИМЯ }}` — в `env` шагов `radar.yml` и `probe.yml`. Тест сверяет все три места: секрет адаптера есть в `SOURCE_SECRETS`, каждый секрет из `SOURCE_SECRETS` просит хотя бы одна сеть, а оба workflow передают ровно эти секреты.
4. **Страница** `docs/sources/<сеть>.md`: что нужно, цена, как получить доступ, пример источника в блоке `json`, что приходит и что нет. Тест проверяет, что на странице сети есть пример источника её типа и он проходит проверку конфига.
5. **Таблицы** в [README](../README.md#какие-сети) и [setup.md](setup.md#2-источники).
6. **Тесты** в [`test/sources.test.ts`](../test/sources.test.ts): ответ в форме живого API, мусор в ответе, классификация ошибок, токен не в адресе запроса.

## Правила

- Токен — в заголовке или теле запроса, не в адресе: адрес может оказаться в логе.
- Без зависимостей во время работы: `fetch` и стандартная библиотека Node.
- Запросы — через `requestJson` или `readText` из [`src/http.ts`](../src/http.ts): там таймаут и предел размера ответа. Свой текстовый формат разбирается за линейное время, без регулярок с ленивыми квантификаторами по чужому тексту: один медленный ответ останавливает опрос всех сетей.
- Тексты ошибок — по-русски, без тел ответов API целиком: лог публичный.
- Платная сеть просит только новые посты: адаптер получает виденные ID в `ctx.known`.

Проверка перед pull request — `npm run typecheck && npm test`.
