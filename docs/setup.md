# Настройка

Порядок: бот → ключ VK → токен Meta → секреты → проба → первый запуск → расписание. Каждый токен вписывается только в секреты репозитория: не в код, не в issue, не в чат.

Команды ниже используют [GitHub CLI](https://cli.github.com/); `OWNER/REPO` — ваш репозиторий. `gh secret set` спрашивает значение сам и не показывает его на экране.

## 1. Бот Telegram

1. В [@BotFather](https://t.me/BotFather): `/newbot` для нового бота или `/mybots` → бот → **API Token** для существующего. Не нажимайте **Revoke**: старый токен перестанет работать везде, где он уже используется.
2. Сохраните токен:

   ```bash
   gh secret set TELEGRAM_BOT_TOKEN --repo OWNER/REPO
   ```

3. Чат для постов. Добавьте бота в группу или канал; в канале боту нужно право публиковать сообщения. ID группы начинается с `-100`. Узнать его: напишите в группу любое сообщение и откройте у себя в браузере `https://api.telegram.org/bot<токен>/getUpdates` — ID лежит в `chat.id`. Если бот уже подключён к другому сервису через webhook, `getUpdates` ответит ошибкой 409 — тогда ID группы возьмите из настроек того сервиса.

   ```bash
   gh secret set TELEGRAM_CHAT_ID --repo OWNER/REPO
   ```

4. Чат для алертов — обычно личка ответственного. Напишите боту `/start` (без этого бот не может писать первым) и узнайте свой ID у [@userinfobot](https://t.me/userinfobot).

   ```bash
   gh secret set TELEGRAM_ALERT_CHAT_ID --repo OWNER/REPO
   ```

## 2. VK

1. В кабинете разработчика [VK ID](https://id.vk.com/) создайте приложение.
2. В настройках приложения скопируйте **сервисный ключ доступа**. Он читает открытые стены сообществ и не привязан к личному аккаунту.

   ```bash
   gh secret set VK_TOKEN --repo OWNER/REPO
   ```

3. В `radar.config.json` у источника VK `ownerId` — минус числовой ID сообщества: для `vk.com/club89236419` это `-89236419`. Короткий адрес сообщества переводится в ID методом [`groups.getById`](https://dev.vk.com/ru/method/groups.getById).

## 3. Meta: Instagram и Facebook

Токен выпускается от **системного пользователя** бизнес-портфолио, а не от личного аккаунта. Личную сессию Meta время от времени аннулирует (смена пароля, проверка безопасности), и тогда интеграция молча перестаёт работать; токен системного пользователя живёт, пока его не отзовут.

Нужно: бизнес-портфолио в [Meta Business Suite](https://business.facebook.com/), которому принадлежат страница Facebook и Instagram-аккаунт; Instagram — профессиональный (бизнес или автор) и привязан к странице.

1. **Приложение.** На [developers.facebook.com/apps](https://developers.facebook.com/apps) создайте приложение типа «Бизнес» и привяжите его к своему бизнес-портфолио. Публиковать приложение и проходить App Review не нужно: оно читает только активы своего же портфолио.
Названия пунктов ниже — из английского интерфейса: он меняется реже переводов.

2. **Системный пользователь.** [Business settings](https://business.facebook.com/settings) → **Users** → **System users** → **Add**, роль — Employee.
3. **Доступы.** У системного пользователя → **Assign assets**:
   - страница Facebook — доступ к контенту (Content) или полный;
   - Instagram-аккаунт;
   - приложение из шага 1.
4. **Токен.** У системного пользователя → **Generate new token** → приложение из шага 1, срок действия **Never**, разрешения:
   - `pages_show_list`
   - `pages_read_engagement`
   - `pages_read_user_content`
   - `instagram_basic`

   Токен показывается один раз. Сразу сохраните:

   ```bash
   gh secret set META_TOKEN --repo OWNER/REPO
   ```

5. В `radar.config.json` у источников Instagram и Facebook `pageId` — числовой ID страницы Facebook, к которой привязан Instagram. Проба из шага 4 печатает его для всех страниц, которые видит токен.

## 4. Проба доступов

Проба читает каждый источник, показывает страницы и Instagram-аккаунты, которые видит токен Meta, и проверяет бота. Состояние не трогает.

```bash
gh workflow run probe.yml --repo OWNER/REPO -f send_test=true
```

С `send_test=true` в чат алертов приходит тестовое сообщение. Результат — в логе запуска (Actions → probe): у каждого источника `OK` и дата последнего поста или `ОШИБКА` с причиной.

## 5. Первый запуск и расписание

Первый запуск запоминает текущие посты и ничего не присылает:

```bash
gh workflow run radar.yml --repo OWNER/REPO
```

После него в репозитории появится ветка `state`. Включите расписание:

```bash
gh variable set RADAR_ENABLED --body true --repo OWNER/REPO
```

Выключить — `gh variable delete RADAR_ENABLED --repo OWNER/REPO`.

## Если пришёл алерт

Алерт называет источник, тип сбоя и что сделать. Частые случаи:

| Тип | Что значит | Что делать |
| --- | --- | --- |
| `auth` | токен отозван или истёк | выпустить новый токен и обновить секрет из алерта |
| `permission` | у токена нет нужного разрешения или актива | проверить назначенные активы и разрешения (шаг 3) |
| `rate_limit` | API попросил подождать | обычно проходит само |
| `network` | API не ответил | обычно проходит само |
| `config` | неверный ID в `radar.config.json` или не задан секрет | сверить с выводом пробы |

После обновления секрета запустите пробу: если всё в порядке, следующий запуск радара пришлёт «снова отвечает».
